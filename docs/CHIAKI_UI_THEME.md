**设计推导：七海的游戏界面。** 游戏原作的黄黑 UI 与七海角色配色是不同来源。本次保留原作的图形语法，把主要配色调整到七海的深青与雾粉；并不声称粉色主题就是原游戏 UI。

不采用上一版的同心环、持续扫描、发光细框、`CHARACTER LINK`、`LOG / 01`、大号品牌水印及宣传式口号。一级优先安静，二级让角色、当前句和输入成为主要信息。

## 4. 像素素材使用

原文件保持不变，使用显示区域裁切，而非生成新图片。原图的透明像素直接保留，青绿色格间区域不进入显示框。

- 图集：490 × 343；5 列 × 4 行。
- 首格左上角：`(10, 11)`；每格显示 `86 × 72`。
- 步长：横向 96、纵向 83。
- 只在任务／设置等辅助面板以 1 倍作为小型状态装饰。主舞台和对话字幕不再叠加像素角色。使用 `image-rendering: pixelated`，不做平滑插值。
- 第一行左起为 0–4，第二行 5–9，以此类推。元数据见 [sprite-atlas.json](../demo/interaction-redesign/sprite-atlas.json)。

| UI 状态 | 使用帧 | 规则 |
| --- | --- | --- |
| 待机 | 0 | 静止，无自动晃动 |
| 聆听 | 3 | 稳定姿势；实际录音状态由单独标记表达 |
| 识别／思考 | 4、5 | 手持屏幕的两种画面，450 ms 离散切换 |
| 转写确认 | 4 | 保持一帧，等待用户操作 |
| 回应 | 17、18 | 两个表现性姿势轮换，不声称是音素口型 |
| 停止 | 0 | 即刻停止循环 |
| 离线／语音故障 | 8 | 灰色屏幕姿势，配明确故障短句 |

这些映射是本应用的设计选择，并非已经核实的原游戏动画序列。其余素材先保留，不为了用全素材而添加音乐、攻击或清扫等难以理解的操作状态。

原型中停止或代数改变后，旧事件不重新启动角色状态。减少动效时固定第一帧；页面不可见时不推进帧。正式 QML 需要依据所在输出的缩放选择整数物理像素倍率，并在隐藏时停掉计时器。

## 5. 两级呈现

**一级常态：角色与图标。** 默认只显示立绘／3D 和小操作条：文字、麦克风、发送／停止、任务、沉浸入口。空闲没有常驻对话卡。录音、识别、回复处理和异常仅显示必要状态；转写待发送时在操作条左侧显示深青卡片；角色回复在头部左侧显示仅含正文的淡粉气泡，结束后保留约 5 秒再收回。文字可换行，长转写在卡片内滚动，不强迫展开。

| 内容来源 | 位置 | 色彩与形状 | 操作 |
| --- | --- | --- | --- |
| 你的转写 | 操作条左侧，与操作条底部对齐；不放在正上方 | `#244344` 深青底、`#D8EEEA` 青白字、浅青边线；直角斜切卡片，短横线指向操作区；麦克风 +「待发送」 | 直接点击文字编辑；浅青箭头或 Enter 发送，Shift+Enter 换行；清空时禁用发送 |
| 七海回复 | 角色头部左侧，靠近脸部但避开角色轮廓 | `#EAD7E0` 淡粉底、`#382C3A` 深梅色正文；细描边、轻阴影、柔和转角与小尾角；只保留正文，无名字或图标 | 当前回复结束后短暂保留；需要完整记录时使用操作条的文字入口 |

窄屏仍保持转写在操作区左侧，操作图标换为两列；回复移到角色头部上方，避开脸部，不与转写共用位置。一级展开卡里的转写预览与确认输入也使用深青系，角色历史消息维持粉／紫系。

**一级展开项：上一版的小对话卡。** 只有主动点击操作条的文字图标才显示约 338 px 宽的小卡；最近一问一答、输入框、转写编辑、上下文和发送功能均保留。收起卡片只改变显示，草稿、未处理转写与本轮语音保留，角色位置不变。小卡属于一级内部展开，不增加新的层级。

**常态语音流程：麦克风 → 录音中 → 勾号结束 → 识别 → 左侧卡片显示转写 → 箭头直接发送 → 单句回复。** 全程不展开文字卡，也不进入沉浸页。勾号是完成采集，方块是取消；单次模式始终需要主动点击发送。需要修正时直接点击左侧卡片里的文字，无需打开小卡；修改实时保留，之后点击箭头或按 Enter 发送。Esc 退出输入焦点但保留修改；中文组合输入的确认不会触发发送。

如果已有文字草稿，原地修改只修改本次转写；清空转写后卡片保持可编辑，发送禁用，不回退到旧草稿。常态直接发送只提交本次转写，保留原草稿及其附加内容；不把隐藏的草稿或截图一起发送。主动展开小卡后，可以选择替换、追加或放弃转写。语音故障也可以通过文字入口继续交流。

**二级：大角色与完整记录。** 主动点击展开后呈现完整历史、大角色和当前句字幕。记录使用墨紫底板；七海的消息为雾粉／灰紫，用户消息为深青／青白，通过左右位置、边线和斜切方向共同区分。任务卡采用更亮的莓紫底色，正文区不用纹理。两级共享会话、草稿、附加内容、角色显示方式与当前语音轮次。

**角色显示：立绘／3D。** 两种显示方式在两级均可用，切换层级不改变所选方式。主画面同一时刻只呈现一个角色，不搭配第二个像素角色。像素图集保留在辅助面板中，未来也可完全关闭。

本原型默认立绘；3D 选项使用现有角色包经项目 `Character3D.qml` 渲染的透明静态预览，页脚明确标注。它用于验证配色和占位，不是浏览器实时 3D，也不证明动作、口型已接通。正式应用继续复用现有 Qt Quick 3D 渲染器；渲染失败应明确提示并允许切回立绘，不自动变成像素形象。

**展开是布局切换。** 文字卡展开／收起与两级切换都不发送草稿、不清空转写、不打断当前轮次；从二级返回时恢复一级先前的展开状态。持续录音时常态操作条仍显示「录音中」与停止。隐藏保留语音交互与连续模式，锁屏、明确停止、连接断开或完整退出才释放语音，后台任务独立运行。常态转写完成不聚焦隐藏输入框；主动点击转写文字、打开文字卡或沉浸页时才聚焦对应输入。

## 6. 动效与实现

- 取消常驻扫描和旋转。待机主要依靠角色本身成立。
- 按钮按下可以有 1–2 px 位移，选中使用实色块；图标提示延迟约 250 ms 显示。
- 抽屉 170–220 ms；两级切换保留上层方案的连续性目标；图集换帧不插值、不变形。
- 实际麦克风、任务和播放状态继续来自 Host；本原型所有事件均为模拟。
- 配色、边框、图标、图集映射应成为角色主题配置；业务命令与交互骨架共用，后续角色无需复制整套 QML。

本地立绘、像素图集和模型渲染预览通过被 Git 忽略的 `.local/` 接入，不将角色资产、个人路径或含角色素材的预览图提交到仓库。原型也可通过底部「素材」选择 `pixel.png` 与立绘，纯浏览器本地读取，不上传。

## 7. 本轮检查

本轮 JavaScript 语法与独立 Chromium 交互检查通过：原地点击编辑不展开面板；编辑时光标与选区保持；Enter 发送、Shift+Enter 换行、组合输入确认事件不误发；清空后仍可输入且发送禁用；存在旧草稿和附加内容时不会覆盖或误发。文字卡与层级切换保留修改，取消后旧识别／回复不会复活。回复气泡的可见内容只有正文。1440 × 960、1366 × 768 和 390 px 窄屏均检查了布局、点击与长文本编辑。

此前完整流程的验证范围包括：

- 默认只有角色与图标，文字卡隐藏；立绘／3D 切换保留常态。
- 常态完整走通录音、结束、识别、直接发送、回复和气泡收回；全程没有打开小卡或进入二级，转写完成不聚焦隐藏输入。
- 已有草稿及截图时，直接发送只包含本次转写，原草稿和附加内容仍在；识别／生成取消后旧结果不重新出现。
- 文字图标主动打开上一版小卡，角色位置保持；转写冲突、修改、文字发送、收起回常态均可操作。
- 两级切换恢复一级小卡先前的开合状态；连续语音可以保持常态，语音故障与离线显示必要状态。
- 1440 × 960、1366 × 768、390 px 窄屏下，常态与展开项均检查了可视布局及点击区域；无脚本异常，窄屏无横向溢出。

按 sRGB 相对亮度计算，新记录区角色正文对比度为 10.31:1、用户正文 8.84:1、输入正文 14.08:1；任务辅助文字 6.24:1，输入边界 3.56:1。这是上述实色组合的计算结果，不能替代整套 QML 的可访问性验收。

浏览器的本地模型预览由 `Character3D.qml` 在独立虚拟显示上生成，不调用录音或模型服务。正式 Quickshell／Host 现已实现此交互，使用真实模型渲染；独立验证及尚待实机检查的输入区域、焦点、设备和性能见 [实现说明](UI_IMPLEMENTATION.md)。
