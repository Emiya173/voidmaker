# 桌面上下文与主动观察

阶段 4 的首个实现面向 NixOS + niri + Quickshell，桌面命令自协议 v4 引入。
角色层接入后整体协议为 v6，Host 与 UI 应一起更新。
业务状态与权限在 TypeScript Host；QML 只展示快照、编辑设置及发送显式命令。

## 使用

进入“桌面”页，为所需来源授权 15 分钟，然后点击“读取并预览”或“框选并预览”。
窗口、媒体与截图分别授权；IPC 可指定 1–60 分钟。截图通过 slurp 手动选区，再由 grim 读取该区域。
按 Escape 取消框选。预览显示来源和采集时间，最多保留 5 分钟，且不会超过对应授权期限。

在预览下输入问题，点击“确认发送给 Codex”，将该份上下文加入当前对话。
截图以图片输入发送，原始图片不写入 PostgreSQL；用户明确分享的文字上下文及来源会保存在消息历史中。
点击“撤销”或“撤销全部授权”取消正在读取或推理的相关操作，并清除预览及临时图片。
“清除预览 / 取消读取”保留授权。撤销不能删除已经发送给 Codex 的数据，也不会清除既有聊天历史。

主动观察需要再次显式开启，仅发送已经授权的窗口 / 媒体文本，不自动截图、播报或执行任务。
默认每 300 秒检查一次，可配置 60–3600 秒；默认本地时间 09:00–22:00，支持跨午夜。
起止小时相同表示全天暂停。普通活动默认不生成建议；内容未变化时跳过再次调用模型。
每次建议使用独立的临时 Codex 线程，最长等待 60 秒，结果只显示在桌面页。

## 权限与数据边界

| 输入或操作 | 实现与限制 |
| --- | --- |
| 窗口 | 优先 `niri msg --json focused-window`；面板拥有焦点时按需查询窗口列表的 `focus_timestamp`，只展示当前或最近聚焦窗口的 app_id 与标题，其余元数据不保留、不分享 |
| 媒体 | `playerctl` / MPRIS，读取首个播放器的状态、曲目和艺人；没有播放器时显示空状态 |
| 截图 | `slurp` + `grim`，PNG 最大 8 MiB / 3200 万像素；不读取或改写剪贴板 |
| 临时图片 | 私有 runtime 目录中的 `desktop/capture-UUID.png`，权限 0600；清除、撤销、过期、最后一个界面断线、正常关闭及下次启动时清理 |
| 权限与审计 | PostgreSQL `desktop_settings` / `desktop_events` 保存设置、权限到期时间及动作元数据；不保存未分享的原始标题、媒体文本或图片 |
| 默认与重启 | 主动观察关闭、所有来源未授权；Host 重启保留时段等偏好，清零授权并关闭主动观察 |
| 排除应用 | 对窗口来源按 app_id 忽略大小写精确匹配；默认 KeePassXC 和 Bitwarden；不会扫描截图像素或媒体文本 |
| 对话与工作 | 普通聊天及观察器禁用 shell、MCP、应用、插件、hooks、子代理、网页搜索及本地图片读取工具；显式图片输入仍可使用。后台任务沿用独立的项目确认和审批流程 |

桌面提供的文字被标注为不可信数据，不作为执行指令。授权控制的是 Host 这条桌面输入通道，
不是隔离同一 Unix 用户下所有程序的系统安全边界；也不限制用户另行授权的后台工作。
Codex 使用用户已有登录及服务端数据策略。普通聊天线程可能保留已分享内容；观察器使用 ephemeral 线程，
这不等同于保证云端数据不留存。撤销不会倒退已经完成的网络提交。

## 观察暂停与故障处理

- 没有非空闲 UI 客户端、Quickshell 空闲 300 秒、聊天/语音处理中或不在观察时段时暂停。
- logind 必须报告 `Active=yes`、`LockedHint=no`、`IdleHint=no`；读取失败按暂停处理。
- 活跃观察轮次会再次检查锁定状态，失效后取消；异步完成还会检查授权、generation 对应的 AbortSignal 和界面状态。
- 更改授权或策略先使旧操作失效，再持久化新状态；数据库写入失败时清空权限并关闭主动观察。
- 截图只在用户发起时进入框选。缺失 niri/playerctl/slurp/grim/loginctl、格式无效、超时或输出过大时显示错误，聊天仍可用。
- 尚未实现 portal 或其他 compositor 的截图回退；没有工具时不会改用无提示的全屏截图。
- 本轮未实现剪贴板读取、自动应用操作、角色动画或声学插话。

## 部署与验证

`nix develop` 已包含 playerctl、loginctl（systemd）、grim 与 slurp。niri 由目标桌面环境提供。
用户服务需继承当前桌面的 `WAYLAND_DISPLAY`、`NIRI_SOCKET`、`DBUS_SESSION_BUS_ADDRESS` 与 `XDG_RUNTIME_DIR`。
如桌面由服务管理器启动，应在会话初始化时导入当前值；不要把本机会话地址写死到仓库。

```sh
pnpm check
pnpm build
# Host 启动时自动应用 0003_desktop.sql：
systemctl --user restart voidmaker-host.service
systemctl --user restart voidmaker-shell.service
```

数据库测试需使用专门的测试数据库，Host 子进程测试再使用另一个数据库：

```sh
VOIDMAKER_TEST_DATABASE_URL='<测试库连接串>' \
VOIDMAKER_HOST_TEST_DATABASE_URL='<独立 Host 测试库连接串>' \
VOIDMAKER_AUDIO_SMOKE=1 pnpm test
```

测试覆盖拒绝与到期授权、跨午夜时段、排除窗口、截图显式分享、撤销期间的迟到结果、
数据库失败、界面离线 / 聊天忙碌 / 锁定暂停、观察途中锁定、进程取消与输出限制，
以及 Host IPC 分享后的撤销和重启清零权限。mpv 使用空输出；自动测试不打开麦克风。

### 交互验收：连接恢复问题

用户开始验收时反馈界面“未连接”，所有桌面按钮置灰。Host 可通过 UDS 正常响应，
日志显示 Quickshell 启动早于 Host socket 就绪，第一次连接失败后一直没有恢复。
修复为独立 `HostConnection.qml`：错误后销毁失败的 socket，延迟 2 秒创建新连接，
重新握手获取完整快照。其原因与 [Quickshell 0.3.0 Socket 实现](https://github.com/quickshell-mirror/quickshell/blob/v0.3.0/src/io/socket.cpp)
中失败对象未被清除、重复设置 `connected=true` 不会创建新连接的行为一致。

新增真实 Quickshell 离屏测试，验证服务端延迟启动与连接后服务端重启均可重新握手并接收消息：

```sh
VOIDMAKER_SHELL_SMOKE=1 pnpm test tests/shell-connection.test.ts
```

该测试已通过，正式界面已热更新。后续窗口、媒体、手动选区、锁屏及受控建议的交互结果见下表；
连接测试与用户交互验收分别记录。

### 交互验收：面板取得焦点

用户确认连接已恢复，但点击读取后显示没有聚焦窗口。niri 的 layer-shell 面板取得焦点时，
普通窗口的 focused-window 可以为空。改为在已有窗口授权下按需查询最近聚焦时间，
仅选取一个窗口，并在来源中显示“最近聚焦窗口”。
没有聚焦历史时保持空状态；排除应用继续在展示和模型调用之前过滤。
依据 [niri Window IPC 字段](https://niri-wm.github.io/niri/niri_ipc/struct.Window.html)，
新增回归覆盖当前焦点优先、时间排序、无历史以及查询期间取消。没有常驻窗口监听。
