日期：2026-09-26。录音、转写与详细 JSON 指标仅存本机 XDG state 下的验收目录，不入库。

**最新结论：参考音量修正后的实机纯回声衰减约 17.5 dB，仅人声与双讲样本均能正确转写；
但用户通过同增益对照确认 AEC 后“数据库”仍无法听清，双讲听感未通过。应用仍未接入 AEC。**

- ASR：Qwen3-ASR-0.6B，本机 Transformers / ROCm 服务。

处理后从虚拟 source 输出。同时另录一份原始麦克风作为对照。
没有改动系统默认输入 / 输出或持久音频配置；AEC 测试不调用 Codex。

## AEC 方法

新增有人值守工具 `pnpm aec:smoke`，要求显式 `--confirm-microphone`，不会加入自动测试。
工具读取给定的 5–25 秒 PCM WAV，按需建立临时 AEC 节点，同时记录两路 16 kHz 单声道 PCM。
开启自动超时与信号清理，不修改默认设备；结果文件与目录使用私有权限。
AEC 关闭自动增益与噪声抑制，以减少额外处理对回声衰减比较的影响。

```sh
pnpm aec:smoke --confirm-microphone \
  --input '<物理麦克风 node.name>' --sink '<物理扬声器 node.name>' \
  --reference /path/reference.wav --directory /path/new-private-result \
  --mode echo
```

- `echo`：人保持安静，仅扬声器播放参考音频，测两路能量并检查 ASR 回采。
- `near`：不播放参考音频，用户正常朗读，检查人声保留。
- `double`：播放参考音频时用户朗读，检查双讲下的人声与 ASR。
- 只有 `echo` 的能量差用于解释回声衰减；`near` / `double` 不能当作 ERLE。
- 比较区间从录音第 4 秒至参考音频时长，避开部分初始收敛；未单独校准两路群延迟。
- 首轮路由正确，但工具把 `pw-record --sample-count` 完成后的退出码 1 当作失败，未产生有效报告。
  已根据 [PipeWire 1.6.6 pw-cat 实现](https://github.com/PipeWire/pipewire/blob/1.6.6/src/tools/pw-cat.c)
  修正：仅在样本数完全匹配且 stderr 为空时接受该特定完成情况；任一录音不足仍报错。

## 双讲失败后的排查

使用已有录音直接驱动本机 SPA AEC 插件做离线对照，未启动麦克风、扬声器或 Codex。
本机 PipeWire 1.6.6 实际链接 WebRTC Audio Processing 2.1。诊断用的最小原生插件调用器、
输入与输出均放在本机验收目录，不是应用依赖；评测编排与 ASR 调用使用 TypeScript / JavaScript。

旧录音没有记录 AEC 内部参考轨，因此按参考文件与约 1 秒播放起点重建参考，不能视为逐样本精确回放。
16 kHz 下比较参考偏移 0.9 / 1.1 秒、参考增益 1 / 0.1 / 0.02 及 mobile mode，共 24 组；
随后以实际 AEC 工作采样率 48 kHz 对 1 秒偏移、两档增益与 mobile mode 做 8 组对照。

48 kHz、默认非 mobile 模式的关键结果：

| 参考增益 | 双讲 CER | 首句片段能量差（第 3–6 秒） | 纯回声能量差（第 4–14.64 秒） | 纯回声 ASR |
| --- | --- | --- | --- | --- |
| 1 | 42.3% | 26.9 dB | 17.1 dB | 空 |
| 0.02 | 0% | 2.7 dB | 15.8 dB | 空 |

已复现相同首句丢失，且参考幅度对结果有显著影响。0.02 仅是离线对照档位，不能写成固定设备配置。
这支持继续排查参考电平与初始收敛，但没有证明所有设备上均由单一原因造成。
mobile mode 在部分时序下仍出现漏字，降低参考增益时也可能丧失回声抑制，未选为默认修复。

验收工具增加 `--reference-mode monitor`：将测试语音直接送入指定物理 sink，从其 monitor
获取参考，并根据运行时读取的线性软件音量修正参考电平。仅支持未静音、各声道等音量、
可验证为软件音量的输出；不把 `wpctl` 的 UI 音量百分比直接当作线性增益。
若 monitor 已应用输出音量，则不重复施加。测试开始 / 结束的音量不一致时判为无效。
这是固定音量的诊断实现，尚未处理生产场景中的实时音量变更。

`--debug-audio` 额外保存 PipeWire 内部参考 / capture / 输出的三声道浮点 WAV 与音频图快照，
用来验证实际送入算法的信号。所有诊断数据保存在指定私有目录，临时节点结束后释放。
原来的虚拟 sink 路径仍可用 `--reference-mode sink` 做基线对照。设备目标禁止自动回退。

依据：[PipeWire 1.6.6 AEC 插件实现](https://github.com/PipeWire/pipewire/blob/1.6.6/spa/plugins/aec/aec-webrtc.cpp)、
[Echo Cancel 模块与内部 WAV 导出实现](https://github.com/PipeWire/pipewire/blob/1.6.6/src/modules/module-echo-cancel.c)。
新路径尚待实机复测，不能以离线结果覆盖前述双讲失败结论。
