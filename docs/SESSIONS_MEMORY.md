# 会话与手动长期记忆

## 本轮功能

2026-09-26：协议升级为 **v6**，Host 和 Shell 必须一起更新。迁移 `0005_history_memory.sql` 为已有角色会话补充元数据，保留原来的消息与 Codex 线程。

在「会话与记忆」页可以：

- **会话**：新建并切换、改名、归档、恢复、删除已归档会话。当前会话须先切换才能归档或删除；删除需要界面确认。
- **历史**：搜索指定会话的消息，按最新在前显示，每页 50 条，继续加载更早记录。归档记录也可浏览。
- **记忆**：手动新增、查看、修改、停用、启用或删除事实与偏好。范围可选择当前角色的所有会话，或仅当前会话；已有条目不能直接改范围。

普通对话页仍显示最近 200 条消息；完整历史由管理页分页查询。标题和消息搜索为大小写不敏感的字面子串匹配，`%`、`_` 不当作通配符。

会话与角色使用各自的 Codex 线程；选中会话持久保存，重启后恢复。回复、录音、播报和连续模式运行时，Host 拒绝切换或修改会话/记忆；先点击「停止」。多个界面同时修改时，修订号冲突会被拒绝，刷新后再编辑。

## 记忆如何进入模型

记忆来源目前只有用户手动输入，不自动从聊天推断事实。界面明确提示启用的记忆会发送给 Codex，后台任务与主动建议不会自动使用这些记忆。

- 查询同时限定 **角色 ID + 角色配置版本**，再筛选本角色通用条目与当前会话专用条目。
- 纯函数 `memoryInstructions` 排除停用和其他会话的条目，将资料附加到角色上下文；资料不授予工具权限。
- 新增、修改、停用、启用、删除记忆与受影响线程解绑在同一数据库事务中提交。
- 角色记忆变更影响该版本角色的全部会话；会话记忆仅影响该会话。
- **下一次发送会创建新模型线程**，采用最新记忆。旧消息仍在本地可查，但不重放给模型，因此先前聊天上下文也会被重置。这避免将已删除的记忆从旧聊天重新带入上下文。
- 删除记忆不会清除历史消息中出现过的内容，也不会从 Codex 的历史线程存储中物理擦除旧记录；VoidMaker 不再恢复这些已解绑线程。

每条最多 2000 字；每个角色配置版本总共最多 100 条、20000 字，停用条目也计入保存限额。超过限额会回滚本次更改，保留原有条目与线程。

## 实现与边界

| 层 | 职责 |
| --- | --- |
| `packages/contracts/src/history.ts` | 命令边界、修订号、分页/记忆投影 |
| `packages/domain/src/memory.ts` | 纯函数选择并格式化有效记忆 |
| `packages/adapters/src/history-store.ts` | PostgreSQL 参数化查询、事务、范围限制、配额、线程失效 |
| `apps/host/src/character.ts` | 角色/会话选择与编辑互斥；准备失败保留当前绑定，关闭后拒绝迟到切换 |
| `apps/host/src/main.ts` | IPC 编排与线程创建，当前轮次绑定快照及 generation 检查 |
| `apps/shell/HistoryPanel.qml` | 声明式展示与表单；请求编号过滤过期分页结果 |

游标使用记录 UUID，在数据库中比较 `(created_at, id)`，避免 JavaScript 毫秒时间转换丢失 PostgreSQL 微秒精度；每页有界，搜索无 SQL 字符串拼接。

删除已归档会话会同时删除本地消息和该会话专用记忆，不删除角色通用记忆。归档只是隐藏于普通列表，不会删除数据。

角色配置版本仍为隔离边界：更改角色包后，旧版本记录继续保留，但跨版本浏览/导入未实现。不存在的角色包同样不会自动暴露旧记录。
