## 1. 产品形态

**让角色成为交流对象，让界面围绕正在发生的交流展开。**

主体验只保留两级。一级是桌面陪伴，二级是角色主导的沉浸交流。任务、历史、记忆、桌面上下文和设置都是按需打开的辅助视图，不建立第三级展开，也不把任务管理作为另一个日常主界面。

```text
第一级：陪伴
  常态：立绘／3D + 图标条 + 必要时的单句气泡
    └─ 文字图标：展开小对话卡，保留上一版完整基础交互
         │ 主动点击「沉浸」／配置的快捷键
         ▼
第二级：沉浸交流
  角色舞台 + 当前句字幕 + 统一输入 + 可折叠对话记录
         ├─ 任务抽屉：草稿、审批、进展、结果
         ├─ 上下文预览：本次准备分享什么
         └─ 会话、记忆、角色及设置
```

默认启动到第一级。二级由用户主动打开；新回复、任务完成、普通错误均不抢焦点、不自动把桌面切成沉浸视图。原型默认进入一级常态，文字卡收起。语音入口与识别完成不打开文字卡；评审工具可直接切换二级。

## 2. 当前问题与重设计决策

以下依据当前代码审查，不冒充真实桌面上的视觉验收。

| 当前实现 | 对体验的影响 | 重设计决策 |
| --- | --- | --- |
| `shell.qml` 中角色为左下角 280 × 490 面板，功能为右下角 540 × 860 面板 | 角色、字幕、输入分散在屏幕两侧 | 统一两级展开和角色空间；字幕靠近角色，输入与状态就近呈现 |
| 对话、桌面、后台任务、会话、设置使用五个平级标签 | 工程模块成为主导航，日常交流缺乏重心 | 沉浸交流成为二级唯一主场景；其余进入辅助视图 |
| 任务转换、开始说话、连续模式、转写、发送、停止占多行 | 状态变化时布局挤动，主动作不突出 | 一个输入组件，一个稳定的开始／结束／停止位置；语音模式作为次级选择 |
| 角色字幕与 `VoiceControls` 字幕分别显示 | 同一句话重复，阅读焦点分散 | 一个当前句字幕投影；记录区保存历史，明确区分「当前」和「上一句」 |
| 消息使用近似等权的整块底色，颜色和尺寸散落在组件里 | 阅读层级与组件一致性不足 | 建立统一主题、文字层级、按钮状态和语义颜色 |
| 每次文本增量都调用 `positionViewAtEnd()` | 阅读历史时容易被拉回最新位置 | 仅在用户原本位于底部时自动跟随；否则显示「有新回复」 |
| 输入框 `enabled` 直接绑定 `canSend` | 回复期间连草稿也无法编辑 | 草稿始终可编辑；提交权限独立于编辑权限；首版不隐式排队发送 |

依据：[主界面](../apps/shell/shell.qml)、[语音控件](../apps/shell/VoiceControls.qml)、[角色视图](../apps/shell/CharacterView.qml)、[3D 角色视图](../apps/shell/Character3D.qml)。现有角色渲染已有骨骼／动作相关能力，重设计应复用并验收，不回退成只有静态头像的聊天界面。

## 3. 第一级：桌面陪伴

### 构图与占用

- 默认右下侧，角色可选立绘或 3D；角色初始建议宽 220–280、高 380–500 **逻辑像素**。保留 24–40 的屏幕边缘安全区。
- 常态只显示角色与一排图标：文字、麦克风、发送／停止、任务、沉浸入口。角色和透明留白不拦截桌面，图标条独立命中。
- 转写在操作条左侧显示为深青的待发送卡片，底部与操作条对齐；转写文字可以原地编辑；角色回复在头部左侧显示为淡粉气泡，只保留正文，去掉名字与图标，用细描边、轻阴影和小尾角呈现。位置、颜色和形状区分输入与回复。回复结束后约 5 秒收回。窄屏保持转写在操作区左侧，回复移至头部上方。
- 上一版 320–350 宽的小对话卡作为一级内部展开项：点击操作条文字图标后出现，包含最近一问一答、输入框、转写处理、麦克风与发送／停止；仍可独立完成基础交互。
- 文字卡展开不改变角色位置；收起保留草稿、转写、附加内容与活动轮次，焦点回到文字图标。从沉浸页返回时恢复先前的文字卡状态。
- 长回复可主动打开小卡滚动查看；常态可直接完成语音交流，修改转写是可选动作。

### 基础交互

| 意图 | 一级内完成的流程 |
| --- | --- |
| 文字聊天 | 文字图标 → 展开一级小卡 → 输入／修改 → Enter 或发送箭头 → 原地看到回复 |
| 常态单次语音 | 麦克风 → 录音中 → 勾号结束 → 识别中 → 左侧卡片显示转写 → 箭头直接发送 → 单句回复；全程不展开 |
| 修改转写（可选） | 点击左侧卡片中的文字 → 原地修改 → 箭头或 Enter 发送；无需展开小卡 |
| 有草稿时转写 | 常态可直接发送本次转写，原草稿与附加内容保留；主动打开小卡才选择替换／追加／放弃 |
| 取消 | 录音／识别／回复时按方块或 Esc → 本轮停止；迟到事件失效，未发送草稿保留 |
| 连续语音 | 主动开启循环模式 → 录音／结束说话 → 自动发送与回复；有草稿时退出自动发送、先处理冲突 |
| 进入沉浸 | 点击独立的沉浸图标 → 完整记录与大角色；同一会话、草稿、附加内容、显示方式和活动轮次延续 |

单次转写只把语音变成待发送文字，不直接触发模型；常态箭头可直接发送这段文字，无需打开面板或修改。连续模式的自动发送在开启时说明。原型的录音、识别与回复均为模拟；真实声音结束检测、设备与服务接入在实施阶段验收。

角色本体默认点击穿透，输入和按钮单独命中。不把触摸身体作为唯一展开方式。任务需要审批时只显示待处理标记，点击才打开审批。

一级保持连续对话时，采集标记与停止必须持续可见；空闲角色状态不等于麦克风关闭。

## 4. 第二级：沉浸交流

### 构图

二级是一块有明确边界的角色舞台：初始建议占可用屏幕宽度的 72%–90%，上限约 1440 逻辑像素，高度由可用区域决定。1920 × 1080、100% 缩放可从约 1280 × 900 开始调校；所有尺寸以实际输出的逻辑可用区域钳制，不能沿用固定 860 高度。

```text
┌─ 连接状态 · 当前角色 / 会话 ─────── 记录  任务  设置  收起 ─┐
│                                                          │
│          角色主舞台                     对话记录           │
│    半身／七分身，脸部在上三分之一        可折叠、可回看      │
│    斜切色块与半调，避开脸部区域       不抢最新句的权重    │
│                                                          │
│    当前句字幕                                            │
│    角色名 + 播报状态 + 1–3 行文本         统一输入区        │
│                                                          │
│       语音状态 / 停止                   上下文 / 发送      │
└──────────────────────────────────────────────────────────┘
```

- **角色主舞台约 60%–68%，记录与输入约 32%–40%。** 面部、手势、口型是第一视觉层，文字是第二层，状态图标与装饰图形是第三层。
- 对话记录可折叠；折叠后角色保持稳定机位，输入保留在原区域，避免每次展开记录都重新裁切角色。
- 字幕靠近角色胸部以下的空白区域，避开脸部与主要手势。播报当前句高对比；结束后的文本标记「上一句」，不能继续显示正在播放。
- 长回答使用按句／段显示和完整历史，不用无法阅读的快速滚动。没有逐字播放对齐数据时，只显示句级字幕，不制造卡拉 OK 式假同步。
- 输入区支持文字、可编辑转写、此次附加内容、语音模式和提交。输入为空时突出麦克风；有文本时突出发送；活动轮次保留停止。
- 单次语音不默认自动发送。连续模式的自动发送规则在开启时说明，后续用持续可见的模式标记反馈。

当可用宽度不足约 1000 逻辑像素时，角色与当前句优先，历史改为抽屉，输入放到底部。较低高度时先缩减角色舞台和装饰，再减少历史空间；停止、字幕和输入必须始终可达。浏览器窄屏原型只用于检查退化布局，不构成移动端产品承诺。

### 两级展开动画

展开用约 280–360 ms：舞台边界显现 → 角色连续移动和缩放至目标机位 → 字幕、输入和记录在最后约 100 ms 内出现。角色保持同一实例或连续视觉身份，不能闪退后重建。正常状态下二级内的角色机位固定。

收起按相反顺序完成。**两级切换保留当前轮次与草稿，一级仍能完成交流。** 收起时如果正在录音，一级继续明确显示录音中与停止。完全隐藏 UI 也保留语音交互与连续模式；锁屏、明确停止、连接断开或完整退出才终止语音并退出连续模式，后台任务独立运行。

## 5. 视觉系统：七海角色主题

完整调研、配色和图集坐标见 [七海 UI 主题](CHIAKI_UI_THEME.md)。本节替代第一版深蓝／青色仪表方向。

- 深青黑舞台、雾粉姓名标签、墨紫记录底板，色彩靠近角色；参考原作的斜切构图和漫画式层级。
- 删除宣传口号、英文编号、品牌水印、同心环与常驻扫描。角色、当前句、输入构成主要信息。
- 历史、任务、设置、语音、连续模式、发送使用图标；悬停与键盘焦点给出短名称。
- 待机用麦克风关闭图标；采集期间明确显示「录音中」。错误、草稿冲突和审批保留必要短文案。
- 主角色在两级都为立绘／3D 二选一，不再搭配像素角色。用户提供的像素图集保持原样，仅用于辅助面板的小型状态装饰。
- 角色消息为灰紫底与浅粉正文，用户消息为深青底与青白正文；斜切方向和边线位置同时区分来源，避免只靠颜色。
- 字幕正文使用正常中文字体，不以像素字体牺牲阅读。主题属于配置，业务状态与两级骨架共用。

## 6. HMI：状态可理解，动作可预测

### 交流状态

| 状态 | 用户看到的反馈 | 主要动作与退出 |
| --- | --- | --- |
| 待命 | 角色中性待机，明确「麦克风已关闭」 | 开始说话或发送文字 |
| 准备语音 | 正在准备，不能提前显示「正在听」 | 可停止；准备失败进入可恢复错误 |
| 聆听 | 粉色活动条、实际输入音量、明确麦克风状态 | 结束说话进入识别；停止直接丢弃本轮采集 |
| 识别 | 整理转写的状态；此时不伪造实时识别文本 | 可取消；结果按单次／连续规则处理 |
| 转写确认 | 输入框可编辑，显示尚未发送 | 发送、修改、清空；原草稿不能被静默覆盖 |
| 思考 | 简短处理状态；角色小幅思考动作 | 可停止；超过阈值显示已等待时间，不捏造完成比例 |
| 准备播报 | 文字可见，语音正在准备 | 可停止；合成失败仍保留文字结果 |
| 播报 | 当前句字幕、实际播放活动、播放驱动口型 | 停止；只有能力可用时才提示语音插话 |
| 正在停止 | 立即退出聆听／播报动画，显示停止处理中 | 在 Host 确认释放采集／播放后回到待命 |
| 离线／服务异常 | 草稿保留；错误说明放在受影响控件附近 | 恢复连接或查看设置；可用的文字功能继续可用 |

麦克风事实应由 Host 投影，不能仅用 `phase === listening` 猜测：连续 AEC／插话模式可能在思考或播报时仍保持采集。当前 `VoiceSnapshot` 有阶段和能力字段，实施时应检查并补齐实际 capture/playback 状态，保证指示器可信。

识别完成时若已有草稿，本次转写与草稿分别保留；原地编辑仅改变转写，即使清空也不会回退到原草稿。清空后输入卡保留，空内容不能发送。常态箭头只发送左侧卡片中的本次转写，原草稿和附加内容不动；主动展开文字卡后提供「替换 / 追加 / 放弃」。正式实施仍需接入真实转写代数。

### 输入、焦点与停止

- Enter 发送，Shift+Enter 换行；输入法组合输入期间 Enter 不触发发送。
- 生成期间可编辑下一条草稿，但不自动排队。停止按钮不变成模糊的「返回」。
- Esc 优先关闭当前明确的弹出选择器；没有弹出选择器且本轮活动时，先停止本轮；再次 Esc 关闭辅助面板／收起二级／收起一级文字卡。单次按键不同时停止又收起。
- 全局唤出／停止快捷键由 niri 配置，安装前检查冲突；原型不把浏览器快捷键等同于全局快捷键。
- 一级常态不请求输入焦点，语音识别完成也不展开、不聚焦隐藏输入。用户直接点击转写文字即可原地编辑，也可主动点文字图标展开小卡；主动进入二级时聚焦同一输入，切换不重建草稿。完全隐藏时恢复原应用焦点；关闭抽屉恢复触发位置的焦点。
- 停止使 generation 失效，旧转写、旧回复、旧 TTS 完成事件不得重新激活字幕、角色口型或连续模式。

### 任务与审批

任务从对话中的具体意图进入草稿卡，卡片说明项目、允许范围、预期产物和完成条件。用户确认后才启动执行。主界面只显示必要的任务摘要和待处理标记。

辅助面板中的任务按「当前状态 → 下一步 → 结果」组织，原始执行日志默认折叠。审批显示操作内容、项目范围、影响、有效期和完整详情；默认动作是允许一次或拒绝。关闭抽屉不等于同意或拒绝，实际过期逻辑由 Host 决定。

取消显示「已停止，已发生的修改会保留」；重启后的不确定任务显示「已中断，待检查」，不展示成完成，也不自动重放。产物只有通过 Host 验证后才标记已完成。

### 桌面上下文、历史与设置

输入框「+」进入选择来源 → 授权 → 读取／手动框选 → 预览 → 附加到本条 → 发送。附加内容显示来源和范围，可移除。授权与发送是两件事；一级不常驻展示长权限说明，用户准备使用时就近解释。

角色／会话选择属于对话标题附近；历史与记忆属于同一辅助视图中的两个清楚入口。角色切换继承现有会话隔离，并在活动轮次结束或明确停止后执行。手动记忆的作用域、修改影响、删除不可恢复需在编辑位置说明。

设置按「外观与角色」「语音与设备」「桌面与隐私」「高级与诊断」组织。日常 UI 使用「语音识别」「朗读声音」等名称；地址、模型参数、AEC 阈值留在高级区域。保存失败保留编辑内容，服务检查不自动录音。

## 7. 角色表现与动态规范

UI 改版和角色质量是两个可分别验收的工作包。当前原型使用本地立绘与现有模型的静态渲染预览评审主题；这不代表正式 3D 建模、材质、动作与口型效果已经验收。

| 状态 | 角色表现 | 状态 / 文本表现 |
| --- | --- | --- |
| 待机 | 轻微呼吸、自然眨眼，较长间隔的小动作 | 常态只显示角色与图标；展开项保留最近回复与输入 |
| 聆听 | 轻微抬头或倾听姿态，视线稳定 | 真实音量驱动活动，不用假波形代替输入 |
| 思考 | 节制的思考姿态，避免每次 token 都重启动作 | 简短处理状态，正文保持可读 |
| 播报 | 播放时钟／实际音量驱动口型，表情不过度切换 | 当前句同步；完整回复进入记录 |
| 打断／停止 | 尽快合口，回到中性过渡，不继续完整演出 | 活动视觉立即停止，等待服务确认 |
| 离线 | 中性静止，不循环「思考」 | 灰蓝状态 + 清楚文字 |

镜头、角色大小、左右摆位、字幕安全区要按外置角色包配置，不在 QML 中写死某个模型的脸部位置。检查半身／全身、手势边界、面部光照、阴影、描边、透明边缘和服装穿插。现有骨骼和形态混合有明确能力边界，复杂演出须以真实素材测试决定。

目标动效节奏：按钮反馈 80–120 ms，字幕换句 100–160 ms，抽屉 180–240 ms，两级展开 280–360 ms。它们是设计目标，不是已测延迟。提供减少动效；关闭视图暂停渲染和无用时间线，隐藏不能继续占用高帧率绘制。

## 8. 实施边界与文件组织

继续使用 TypeScript Host + domain + contracts + Quickshell/QML，不引入第二套应用框架。HTML 仅为设计评审原型。

建议拆分：

```text
apps/shell/
  shell.qml                    # 连接、场景装配和窗口生命周期
  theme/                       # 颜色、字号、间距、动效与通用控件
  views/CompanionView.qml       # 一级
  views/ImmersiveView.qml       # 二级
  components/CharacterStage.qml # 镜头、角色、字幕安全区
  components/SubtitleView.qml
  components/Composer.qml
  components/ConversationLog.qml
  components/StatusIndicator.qml
  panels/                      # 任务、会话/记忆、上下文与设置
```

先把现有 `WorkPanel`、`HistoryPanel`、`DesktopPanel`、`SettingsPanel` 的能力映射到新入口，再按场景重组；不能因为重做外观而丢掉已完成的审批、隔离、错误恢复或配置保存能力。

Host/domain 保存真实状态与规则。QML 保存当前展开层级、抽屉、焦点、滚动位置等短期展示状态；业务状态不移到控件里。UI 展开、关闭、语音停止、后台任务取消使用清楚独立的意图，避免一个 `stop` 意外影响无关任务。

需要重点核对的协议增量：实际麦克风／播放器状态、转写与草稿冲突、字幕代数和播放片段 ID、界面展开与辅助页导航。现有 `phase`、`generation`、`position`、`duration` 等字段先复用；新增字段经过契约校验和版本升级，不能从假 UI 状态推测设备事实。

### Wayland / niri

陪伴角色和沉浸界面可使用 Quickshell `PanelWindow` 边缘锚点与输入区域；其锚定、可聚焦、独占区属性由官方 API 提供，具体行为需按仓库锁定版本实测。[Quickshell PanelWindow](https://quickshell.org/docs/types/Quickshell/PanelWindow)

不为沉浸视图预留永久桌面工作区，不要求壁纸级接管。若以后把重任务详情做成普通窗口，其浮动与初始位置交给 niri 规则，不在应用里添加普通窗口自定位／置顶逻辑。[niri Window Rules](https://niri-wm.github.io/niri/Configuration%3A-Window-Rules.html)

默认只在选定输出显示角色；用户主动在其他屏幕唤出时才迁移。不跟随每次窗口焦点自动跳屏。多屏、缩放、锁屏、全屏、热插拔、输入区域与焦点恢复都需要真实 Wayland 验收。浏览器原型无法证明点击穿透或焦点规则已成立。

## 9. 实施顺序与验收门槛

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| A · 设计定稿 | 本提案、两级原型、状态演示；再以真实角色评审静态构图 | 确认一级占用、二级角色/文字比例、色彩、字幕位置和动效强度 |
| B · 界面骨架 | 主题组件、一级/二级、输入、字幕、记录、焦点与缩放 | 真 QML 能完成展开、收起、文字交流和停止；不再依赖旧五标签主界面 |
| C · HMI 接入 | 语音全状态、任务草稿/审批、上下文、会话与设置 | 正常、失败、取消、断线和重连路径都能解释当前状态并提供下一步 |
| D · 角色与动态 | 真实镜头、角色表现、时间线与低动态模式 | 真实角色无明显裁切/穿插；停止无残留口型/字幕；性能满足目标 |

验收目标：

1. **独立使用**：一级常态完成录音、转写直接发送、接收单句回复与停止，整个流程不得自动打开文字卡或二级。点击文字图标后，小卡可完成输入、修改和完整回复阅读；沉浸入口独立。
2. **状态理解**：用户无需打开设置，就能判断是否正在录音、是否在处理、是否在播放、是否等待自己确认。
3. **布局**：1920 × 1080 / 2560 × 1440；100%、125%、150% 缩放。控件无裁切，字幕不遮脸，输入与停止始终可达。
4. **取消**：监听、转写、生成、合成、播放各阶段都验证停止；模拟延迟到达的旧事件不得恢复该轮。界面按下停止后 100 ms 内给出本地视觉反馈；设备释放延迟另行测量报告。
5. **连续对话**：麦克风实际开启时标记不消失；两级切换后标记仍在；明确停止、完全隐藏或锁屏后确认采集释放。
6. **阅读与草稿**：输入法正常；回复中可写草稿；新增量不拖走历史阅读位置；转写不覆盖已有文字。
7. **桌面行为**：一级透明留白点击穿透，热区可点击；主动输入／展开获取焦点，完全隐藏归还焦点；审批通知不会抢焦点。
8. **性能**：目标为常见展开动画达到显示器可持续帧率，60 Hz 情况以 16.7 ms 帧预算分析；记录实际 GPU、角色复杂度与掉帧。隐藏后无持续角色渲染。数字为目标，非实测结论。
9. **可访问性**：正文对比度目标 ≥ 4.5:1、主要控件边界／焦点 ≥ 3:1；键盘可遍历操作；状态不只依赖颜色；低动态模式保留全部功能。正式色板需实测对比度。

实现阶段运行 `pnpm check`、相关 `pnpm test`、`pnpm build`；状态机与协议变更重点覆盖取消、代数、故障、恢复。QML/Wayland 与模型/设备实机结果分别报告。遵守仓库既有约束：不在无人值守测试中启用麦克风，也不借 UI 设计任务启动已暂缓的语音稳定性专项。

## 10. 本次提案的交付边界

设计与离线原型已落实到正式 `apps/shell` 和 Host。一级常态只显示角色、图标和必要气泡，语音全程不展开；文字与转写收发小卡作为主动展开项。两级共享会话及独立的文字／转写草稿。角色显示为立绘／真实 3D，主舞台没有像素搭配；沉浸记录采用墨紫、雾粉和深青。

浏览器中的 3D 是用项目现有渲染器生成的静态预览，页脚已标注。真实模型资产、本地路径与含角色的截图放在 Git 忽略目录；没有改动原图、现有模型或用户配置。

原型验证见 [主题文档第 7 节](CHIAKI_UI_THEME.md#7-本轮检查)，正式代码与实机验收边界见 [实现说明](UI_IMPLEMENTATION.md)。数据库／模拟服务、真实 QML 和隔离 3D 渲染分别验证，不将这些结果视为真实音频、Wayland 焦点／穿透或 GPU 性能验收。
